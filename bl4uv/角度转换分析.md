# 角度转换问题分析

## 发现的问题

用户报告：在插件中输入角度值3782会获得与Blender原生66相同的效果。

## 数学验证

计算：
```
3782 × π / 180 = 3782 × 3.141592653589793 / 180 ≈ 66.0
```

所以：
- 输入：3782（角度）
- 经过 `角度 × π / 180` 转换
- 输出：66.0（弧度）

## 这意味着什么？

1. **Blender API**：`smart_project()`的`angle_limit`参数需要**弧度**单位
2. **Blender UI**：显示的是**角度**单位（默认66°）
3. **转换**：66° = 66 × π / 180 ≈ 1.1519弧度

但原始代码中：
- 如果用户输入3782°
- 转换：3782 × π / 180 ≈ 66弧度
- 传递给API：66弧度（而不是1.1519弧度）

## 可能的解释

1. **设计错误**：原始代码可能误解了单位
2. **工作区转换**：3782可能是某个特定工作流程中的"魔法数字"
3. **单位混淆**：可能期望用户输入"度×180/π"的值

## 正确的实现

在我的插件中，应该：
1. UI显示角度值（如66°）
2. 内部转换为弧度：`radians(66) ≈ 1.1519`
3. 传递给Blender API

但根据用户的发现，可能需要支持两种模式：
- 模式A：直接输入角度值（66 → 1.1519弧度）
- 模式B：输入转换后的值（3782 → 66弧度）

## 建议解决方案

更新插件以：
1. 默认使用正确的角度→弧度转换
2. 添加选项或说明，解释3782这个特殊值
3. 确保与原始工具的行为兼容
